# 第二幕 · 八把尺子与会升降的戏台

> **给小朋友的话：**
> 上一幕，管理员马库斯学会了认识戏班、给戏班发班牌、安排演员。这一幕，他要学会“排队”：谁先上台？谁后上台？演多久？怎样才算公平？别怕，东方三博士又带来了新的锦囊。
>
> **给大朋友的话：**
> 第二幕对应“处理机调度”。故事之后的“长大了后您会怎么叙述这个故事”部分，按教材口径严格化，重点讲三级调度、调度时机、调度方式、评价指标、七种经典算法和公平调度。

---

## 第一场 皇帝的赏戏大会

上一幕的首演之夜，马库斯用五只锦囊，让三出戏在一座舞台上轮流上演。观众看得如痴如醉，皇帝奥古斯都一世一高兴，下令又建了两座舞台。

现在，大剧场有了三座舞台：太阳台、月亮台、星星台。

皇帝站在阳台上，挥着蜜饯袋宣布：

“从明天起，大剧场要办一场赏戏大会！所有的戏班都可以来，所有老百姓都可以看。但是，我有一条规矩：**要公平，要快，要让观众满意！**”

弄臣在旁边叮叮当当地补了一句：

“陛下，隔壁剧场的戏班可不用等，随到随演！”

皇帝的脸拉长了：“马库斯！你听见了吗？”

马库斯站在台下，手里捧着三座舞台的钥匙，头上冒着三股汗。

“公平、快、观众满意……”他小声嘀咕，“这三个词，怎么听起来像三只猫，一放开就互相追尾巴？”

他赶紧派人去请东方三博士。

三位博士来了，还是那三位老博士，不过这次多了一只大木箱，箱子上写着两个字：

**“调度”**。

高个子博士说：“上一幕，你学会了怎么认识戏班；这一幕，你要学会怎么安排戏班。”

胖博士笑眯眯地补充：“记住，安排得好，三座舞台像六座；安排得不好，三座舞台像半座。”

安静的博士打开木箱，里面整整齐齐放着三只小盒子、八把尺子、七只锦囊，还有一杆金灿灿的小秤。

“我们一件一件来。”他说。

## 第二场 三只盒子：大调度、中调度、小调度

博士先把三只盒子摆在桌上：一只大盒子、一只中盒子、一只小盒子。

“马库斯，你先说说，安排一场演出，你要做哪些决定？”

马库斯掰着手指头：“第一，接不接这个演出合同；第二，戏班要是太多，剧场挤不下怎么办；第三，现在让哪个戏班先上台。”

博士点点头：“很好。这三件事，正好对应操作系统的**三级调度**。”

### 大盒子：高级调度（作业调度）

博士打开大盒子，里面是一叠演出合同。

“这是**作业**。”他说，“作业是用户交给剧场的一项任务，是一份演出合同。它还不一定是戏班——合同可能还躺在柜子里，没有人接。”

“高级调度，也叫**作业调度**，就是管理员从合同柜里挑出一份合同，给它分配内存、道具、化妆间，**组建一个戏班**，把它送进剧场。”

马库斯问：“那是不是每来一份合同，都要接？”

博士摇摇头：“高级调度的频率很低。一份合同通常只被接下一次，组建一个戏班；戏演完了，戏班退出一次。它主要用在**批处理系统**里。分时系统和实时系统通常不这么做，因为它们要求及时响应，合同来了就要尽快处理，不会排成长长的后备队列。”

### 中盒子：中级调度（内存调度）

博士打开中盒子，里面是一张仓库地图。

“剧场再大，化妆间也有限。”他说，“如果戏班太多，剧场挤不下，管理员就会把一些暂时演不了的戏班送到城外的仓库。等剧场空出位置，再把它们接回来。”

“这叫**中级调度**，也叫**内存调度**或**交换调度**。它管的就是戏班在剧场和仓库之间的往返。”

“被送走的戏班，不是解散了。它的班牌还在，戏服还在，只是暂时不在剧场里。它可能是在候场的时候被送走，也可能是在等道具的时候被送走。”

马库斯问：“那中级调度和高级调度有什么区别？”

博士伸出两根手指：

“第一，**高级调度是‘从合同到戏班’，中级调度是‘戏班在剧场和仓库之间搬家’**。一个是从合同里组建新戏班，一个是在已经组建好的戏班之间来回搬。”

“第二，**高级调度通常只在合同开始的时候招收一次，在合同结束的时候送走一次；中级调度可以发生很多次**。今天剧场挤，送出去；明天有空，接回来；后天又挤，再送出去。”

“中级调度的目的，是让更多的戏班有机会在剧场里轮转，而不是把化妆间一次占满。”

### 小盒子：低级调度（进程调度）

博士打开小盒子，里面是一只小小的沙漏。

“这只沙漏，是给舞台用的。”他说，“低级调度，也叫**进程调度**，是三级调度里最频繁、最核心的一个。”

“它做三件事：

1. 保存当前戏班的舞台现场到班牌；
2. 从候场队列里挑一个戏班；
3. 恢复这个戏班的现场，让它上台。”

“低级调度发生得非常频繁。分时系统、实时系统都离不开它。你们看到的‘三出戏同时演’，其实就是低级调度在飞快地换人。”

马库斯恍然大悟：“原来如此！大盒子管有没有戏班，中盒子管戏班在不在剧场，小盒子管谁现在上台。”

博士笑了：“总结得好。再把它们的名字记一遍：大盒子管的是‘从合同到戏班’，中盒子管的是‘戏班在剧场和仓库之间往返’，小盒子管的是‘现在让谁上台’。”

## 第三场 管理员的三个小职员

马库斯问：“低级调度这么忙，我一个人怎么忙得过来？”

博士说：“你不用一个人忙。你的脑子里，应该有三个小职员。”

### 第一个小职员：排队器

“排队器负责维护队列。”博士说，“合同柜放着还没人接的合同，候场区排着等上台的戏班，等道具区排着缺道具的戏班。排队器按照规则，把戏班放进队列、从队列里取出。”

### 第二个小职员：分派器

“分派器负责‘真正让谁上台’。”博士说，“它从候场队列里取出被选中的戏班，把舞台交给它。”

### 第三个小职员：上下文切换器

“上下文切换器负责‘把舞台恢复成戏班离开时的样子’。”博士说，“灯位、道具、演员站位、剧本书签，一样都不能错。”

马库斯问：“那调度器和分派器有什么区别？”

博士说：“**调度器是‘决定谁上’，分派器是‘真正让他上’。** 调度器做决策，分派器做动作。上下文切换器是分派器手里的工具，负责保存和恢复现场。”

## 第四场 什么时候敲锣

马库斯有一面“换戏锣”。他问：“我什么时候该敲锣换戏？”

博士说：“敲锣的时机，就是**调度时机**。记住下面几种情况：”

1. **新戏班成立**：组建了一个新戏班，进入候场队列。这时可以考虑是否让它上台。
2. **戏班谢幕**：戏班终止，舞台空了，必须叫下一个戏班。
3. **戏班去等道具**：戏班阻塞，舞台空了，必须叫下一个戏班。
4. **道具到了**：I/O 完成或事件发生，等道具的戏班被唤醒，进入候场队列。这时可以考虑是否让它上台；如果它更紧急，可以抢占。
5. **演出时限到了**：时间片用完，必须换戏班。
6. **更紧急的戏班来了**：如果采用抢占式调度，高优先级戏班到达时，可以抢占当前戏班。

“有些情况是‘必须调度’，比如戏班谢幕、去等道具、时间片用完。有些情况是‘可以调度’，比如新戏班成立、道具到了、高优先级戏班来了。要不要换，看你的政策。”

马库斯又问：“那什么时候**不能**敲锣？”

博士竖起三根手指：

“第一，**正在处理紧急传令的时候**。传令就是中断。管理员必须先把传令读完，不能读到一半就换戏班，否则传令会丢失，皇帝会生气。”

“第二，**正在执行原子操作的时候**。比如你正在敲着铜锣改五道门的账本，这时候不能换戏班，否则账本会乱。”

“第三，**正在内核临界区的时候**。你手里拿着一把锁，正在改重要的东西；这时候换戏班，可能会死锁，或者让别人看到半成品。”

马库斯想起自己以前犯的错：有一次，他在读皇帝的紧急诏书时敲了换戏锣，结果诏书读到一半，人换了，诏书也断了；皇帝罚他扫了三天马厩。还有一次，他在登记新戏班时敲了锣，两个戏班同时挤进同一间化妆间，账本差点被墨水淹了。

“我记住了。”马库斯说，“**中断处理中不调度，原子操作中不调度，内核临界区中不调度。**”

## 第五场 抢戏派与让戏派

赏戏大会还没开始，剧场里先吵起来了。

一派是**抢戏派**。他们说：“如果有更重要的戏班来了，或者一个戏班演得太久，管理员就应该打断它，让更重要的戏班先上！”

另一派是**让戏派**。他们说：“一个戏班既然上台了，就应该让它演完，或者让它自己下去等道具。管理员不能随便打断，否则演员会忘词！”

弄臣在旁边敲边鼓：“抢！抢！抢！不抢多没意思！”

博士让两派安静下来，说：

“你们说的，就是剧场管理员的两种调度方式：**抢占式**和**非抢占式**。”

### 非抢占式（非剥夺式）

“非抢占式，就是**一旦把舞台交给一个戏班，就让它一直演，直到它谢幕或者自己下去等道具**。管理员不会中途打断它。”

“优点是简单，开销小，适合批处理系统。缺点是，如果一个长戏班霸着舞台，后面的短戏班就得一直等，观众的响应时间会很长。”

“注意：非抢占式不是‘永远不调度’。当戏班谢幕、去等道具时，舞台空了，管理员当然要叫下一个。只是它不会**强行**打断一个还能继续演的戏班。”

### 抢占式（剥夺式）

“抢占式，就是**管理员有权在特定条件下暂停当前戏班，把舞台交给另一个戏班**。比如：”

- 时间片用完（时间片轮转）；
- 有更高优先级的戏班到达（优先级调度）；
- 有剩余时间更短的戏班到达（最短剩余时间优先）。

“优点是响应快、公平，适合分时系统和实时系统。缺点是要频繁保存/恢复现场，开销大。如果处理不好，还可能引起竞争条件。”

博士总结：

| 对比 | 非抢占式 | 抢占式 |
|---|---|---|
| 是否可中途打断 | 不可以 | 可以 |
| 开销 | 小 | 大 |
| 响应时间 | 可能较长 | 较短 |
| 适用场景 | 批处理 | 分时、实时、交互 |
| 例子 | 先来先服务、非抢占 SJF | 时间片轮转、优先级、SRTN |

“所以，没有哪一种一定更好。”博士说，“**批处理系统多用非抢占式，分时/实时系统多用抢占式。** 你要根据剧场的目标来选。”

马库斯想了想，说：“那我让太阳台（贵宾和急事）用抢占式，月亮台（长篇史诗）用非抢占式，星星台（普通戏班）用时间片轮转。这样行不行？”

博士笑了：“行。这就是**混合策略**。”

## 第六场 八把尺子

赏戏大会要评“最佳管理员”，皇帝想知道：怎样才算安排得好？

博士拿出八把尺子，一字排开。马库斯数了数：“一、二、三、四、五、六、七、八。”

### 第一把尺子：CPU 利用率

“舞台不能闲着。”博士说，“CPU 利用率＝有效工作时间÷（有效工作时间＋空闲等待时间）。”

“如果有戏班在候场，舞台却空着，那就是浪费。利用率越高，说明舞台越忙。”

“但也不能盲目追求 100%。”胖博士补充，“如果舞台忙得连换景的时间都没有，戏班就会挤成一团，观众反而看得难受。”

### 第二把尺子：吞吐量

“吞吐量＝单位时间内完成的演出数量。”博士说，“一天演完多少出戏，就是吞吐量。”

“吞吐量高，说明剧场产出多。批处理系统很看重这个。”

### 第三把尺子：周转时间

“周转时间＝戏班完成时间－戏班到达（提交）时间＝执行时间＋等待时间。”

“对观众来说，就是从交了合同，到看完戏，一共等了多久。”

“这里的‘等待时间’是**广义**的，包括在候场区等舞台、在后台等道具、等大屏等所有等待。”

### 第四把尺子：带权周转时间

“带权周转时间＝周转时间÷实际运行时间＝1＋等待时间÷实际运行时间。”

“为什么要除一下？因为长戏班天然周转时间长，短戏班天然周转时间短。直接比不公平。除以实际运行时间，就像给每个戏班量体裁衣，去掉长短的影响。”

“带权周转时间至少是 1；越接近 1，说明等待越少，安排得越好。”

### 第五把尺子：平均周转时间

“平均周转时间＝所有戏班周转时间之和÷戏班数。”

“它用来比较不同调度算法的整体效果。越小越好。”

### 第六把尺子：平均带权周转时间

“平均带权周转时间＝所有戏班带权周转时间之和÷戏班数。”

“它去掉了戏班长短的影响，更适合比较不同算法。越小越好。”

### 第七把尺子：等待时间

“等待时间，通常指**戏班在候场区等待舞台的时间之和**。它不包括戏班在等道具区等道具、等大屏的时间。”

“注意：这和周转时间公式里的‘等待时间’不一样。周转时间公式里的等待是广义的，包括 I/O 等待；而调度指标里的等待时间，通常只算候场时间。两个说法要分开。”

### 第八把尺子：响应时间

马库斯问：“那响应时间是什么？”

博士说：“响应时间，是**从用户提交请求，到系统首次产生响应的时间**。”

“对观众来说，就是从递上戏单，到台上第一次开口。对交互式系统来说，响应时间非常重要；观众可以接受一场戏演得久，但不能接受半天没人理。”

“它和等待时间的区别是：”

- **等待时间**：戏班在候场区里一共等了多久，可能分好几段；
- **响应时间**：从提交到**第一次**得到响应，只看第一次。

“一个戏班可能响应很快，但之后被反复打断，等待时间很长；也可能响应很慢，但一旦上台就一口气演完，等待时间反而不长。”

博士举了个例子：

> 一个戏班 9:00 到达，10:00 第一次上台，演了 10 分钟，被换下；又等了 30 分钟，再上台演 10 分钟，10:50 谢幕。
>
> - 响应时间＝10:00－9:00＝1 小时；
> - 等待时间＝1 小时＋30 分钟＝1.5 小时；
> - 周转时间＝10:50－9:00＝1 小时 50 分钟；
> - 实际运行时间＝20 分钟；
> - 带权周转时间＝110÷20＝5.5。

“看，响应时间只算第一次，等待时间算所有候场时间。不要把两者混为一谈。”

### 尺子之外：还有公平、优先级、资源平衡

博士补充：“除了这些尺子，调度还要考虑：”

- **公平性**：每个戏班都有机会上台，不能饿死；
- **优先级**：重要的戏班可以先上；
- **资源平衡**：舞台、道具、大屏都要合理利用，不能只忙一样；
- **政策执行**：管理员要按皇帝的规定办事，不能随心所欲；
- **可预测性**：实时系统要保证在截止时间前完成。

“这些目标经常互相打架。”博士说，“CPU 利用率高，响应时间可能变长；吞吐量大，平均周转时间可能变差。所以，调度是一门**权衡**的艺术。”

## 第七场 七只调度锦囊

皇帝等不及了：“别讲大道理了，快告诉我，到底怎么排队！”

博士打开第一只锦囊。

### 第一只锦囊：先来先上（FCFS）

锦囊里是一张排队号码牌。

“规则很简单：谁先到，谁先上。”博士说，“这叫**先来先服务（First Come First Serve，FCFS）**。”

“实现也简单，候场队列直接用先进先出队列就行。它是**非抢占式**的。”

马库斯马上试了试。

第一天，长篇史诗《尼罗河上的月亮》第一个到。它一上台，演了三个小时。后面排着的短喜剧《金苹果》只有十分钟，却等了三个小时。观众睡倒了一片。

“这就是 FCFS 的毛病。”博士说，“它**对长戏班有利，对短戏班不利**。一个长戏班堵在前面，后面的短戏班都要陪等，这叫**护航效应（convoy effect）**。”

“优点呢？”马库斯问。

“简单、公平（按到达顺序）、一般不会饿死。”博士说，“但它不适合交互式系统，因为短请求的响应时间可能很长。”

### 第二只锦囊：短戏先上（SJF）

第二只锦囊里是一把短尺。

“规则：**估计运行时间最短的戏班先上**。”博士说，“这叫**短作业优先（Short Job First，SJF）**。”

“它可以是非抢占式，也可以是抢占式。抢占式版本叫**最短剩余时间优先（SRTN，Shortest Remaining Time Next）**：如果新来的戏班剩余时间比当前戏班还短，就抢占舞台。”

马库斯试了试。短喜剧《金苹果》先上，观众笑得前仰后合；接着是《狼奶》；最后才是长篇史诗。平均等待时间一下子短了很多。

“SJF 在‘所有戏班同时到达、运行时间已知’的假设下，能使**平均等待时间最小**。”博士说，“这是它的最大优点。”

“但是，”胖博士补充，“它有三个毛病：”

1. **需要预先知道运行时间**。可戏班常常不知道自己要演多久。
2. **长戏班可能饿死**。如果短戏班源源不断地来，长戏班永远排不上。
3. **有人会撒谎**。弄臣就曾经报了一个“一分钟喜剧”，结果演了三个小时，把后面的戏班全坑了。

“所以，实际系统里，SJF 常常需要配合**老化**（aging）使用：等久了的戏班，优先级慢慢升高，免得饿死。”

### 第三只锦囊：响应比高者先上（HRRN）

第三只锦囊里是一把会伸缩的尺子。

“规则：计算每个戏班的**响应比**，谁高谁先上。”博士说。

```text
响应比 = (等待时间 + 估计运行时间) / 估计运行时间
       = 1 + 等待时间 / 估计运行时间
```

“这叫**高响应比优先（Highest Response Ratio Next，HRRN）**。它通常是**非抢占式**的。”

“它巧妙在哪里？”博士问。

马库斯想了想：“短戏班的分母小，响应比容易高，所以短戏班优先；长戏班等得越久，分子越大，响应比也会慢慢升高，所以长戏班也不会饿死。”

“答对了！”博士说，“HRRN 是 FCFS 和 SJF 的折中：既照顾短戏班，又照顾等久了的长戏班，**不会产生饥饿**。但它仍然需要估计运行时间，而且每次选择都要算一遍响应比，有计算开销。”

### 第四只锦囊：VIP 优先（优先级调度）

第四只锦囊里是一叠金色的 VIP 通行证。

“规则：**优先级高的戏班先上**。”博士说，“这叫**优先级调度**。”

“优先级可以是**静态的**，从戏班成立就定好，不再改变；也可以是**动态的**，随着等待时间、已运行时间等因素变化。”

“它可以是抢占式，也可以是非抢占式。”

马库斯试了试。皇帝的宫廷戏班拿着白金 VIP，一上台就霸着舞台；普通戏班拿着黑铁 VIP，等了一天又一天。

弄臣还偷偷给自己的表弟发了一张“钻石 VIP”。结果，表弟的戏班演得又长又无聊，观众却不敢赶它走。

“这就是优先级调度的最大问题：**低优先级戏班可能饥饿**。”博士说。

“怎么办？”马库斯问。

“两个办法。”博士说，“第一，**老化（aging）**：等得越久，优先级越高；等久了，黑铁也能熬成白金。第二，**动态优先级**：比如一个戏班已经演了很久，就逐渐降低它的优先级，防止它一直霸占舞台；或者，一个戏班等得越久，就逐渐升高它的优先级。”

“还有，”高个子博士补充，“如果低优先级的戏班拿着大家都需要的道具（锁），高优先级的戏班就得等它，这叫**优先级反转**。解决办法之一是**优先级继承**：低优先级戏班暂时继承高优先级，赶紧把道具用完还回来。”

### 第五只锦囊：每人演一小段（时间片轮转，RR）

第五只锦囊里是一只沙漏和一张号码牌。

“规则：每个戏班上台后，最多演一个**时间片**。时间片一到，不管演没演完，都下台，排到队尾。”博士说，“这叫**时间片轮转（Round Robin，RR）**。”

“它是**抢占式**的。时间片通常是固定的，比如 10 分钟、100 毫秒。”

马库斯试了试。每个戏班演一小段就换人，观众一会儿看大力士，一会儿看双胞胎，一会儿看尼罗河的船，觉得三出戏真的在同时进行。

“RR 的优点是**响应快、公平**，适合分时系统和交互式系统。”博士说，“而且，只要时间片不是无限大，一般不会饿死。”

“但是，时间片要选好。”博士拿起沙漏：

- 如果时间片**太大**，每个戏班都能演完才换，那就退化成 FCFS；
- 如果时间片**太小**，管理员大部分时间都在换戏、恢复现场，真正演戏的时间反而少了。这叫**上下文切换开销**。

“所以，时间片要在‘响应快’和‘开销小’之间取平衡。”

### 第六只锦囊：分门别类排队（多级队列）

第六只锦囊里是四个不同颜色的排队牌。

“规则：把戏班分成几类，每类一个队列，每个队列有自己的优先级和调度算法。”博士说，“这叫**多级队列调度**。”

“比如：”

- 皇帝的宫廷戏班，最高优先级；
- 急报戏班，第二优先级；
- 普通喜剧，第三优先级；
- 长篇史诗，最低优先级。

“管理员总是先调度高优先级队列；高优先级队列空了，才调度低优先级队列。每个队列内部可以用自己的算法，比如宫廷戏班用优先级，普通喜剧用时间片轮转。”

马库斯试了试。宫廷戏班和急报戏班很满意，但儿童戏班在最低队列里等了一天，孩子们都哭了。

“这就是多级队列的毛病：**低优先级队列可能饥饿；而且戏班一旦分到某个队列，就不能随便换队列**。它很死板。”博士说。

“那如果戏班的表现会变呢？”马库斯问，“比如一个短戏班演着演着变成了长戏班？”

“那就需要下一只锦囊了。”博士说。

### 第七只锦囊：会升降的戏台（多级反馈队列）

第七只锦囊里是一张画着瀑布的图。

“这是**多级反馈队列（Multilevel Feedback Queue，MLFQ）**。”博士说，“它是多级队列的升级版，也是最灵活的调度算法之一。”

“规则是这样的：”

1. 建若干个队列，编号 0 到 N，**数字越小，优先级越高**。
2. 每个队列都按**时间片轮转**调度；优先级越高的队列，**时间片越小**。
3. 新来的戏班，先进入**最高优先级队列 0**。
4. 如果它在时间片内没演完，就被降到下一级队列的**队尾**；如果还没演完，继续往下降，直到最低队列。
5. 只有在前 0 到 i－1 级队列**全空**时，才调度第 i 级队列。
6. 最低队列通常用 FCFS 或 RR，保证长戏班最终能演完。
7. 如果一个戏班在低优先级队列等得太久，可以把它**升回高优先级队列**，防止饥饿。这叫**老化**。

马库斯照着做了。短喜剧在队列 0 演一小段就谢幕了，观众叫好；长篇史诗在队列 0 没演完，降到队列 1，又没演完，降到队列 2；但它并没有被忘掉，轮到它时照样上台。等得太久的长篇史诗还会被升回高优先级，喘口气。

“这太妙了！”马库斯说，“短戏班能很快演完，长戏班也不会饿死，交互式戏班还能快速响应。”

“是的。”博士说，“MLFQ 不需要预先知道每个戏班要演多久，它能根据戏班的**实际行为**自动调整：短戏班自然留在高优先级，长戏班自然沉到低优先级。它适合批处理，也适合交互式系统。”

“但它也有缺点：”

- 参数太多：队列数、每个队列的时间片、升降级规则、新戏班进入哪个队列……都要调；
- 实现复杂；
- 如果没有老化，长戏班仍可能饥饿；
- 时间片和队列设计不好，可能产生抖动。

## 第八场 公平秤

赏戏大会进行到一半，皇帝又发现了一个问题。

城里有个贵族，家里养了一百个戏班；乡下有个村子，只凑出一个戏班。贵族的一百个戏班把舞台占得满满的，村子的戏班等了一天也没上台。

“这不公平！”村长说。

“可我的戏班多呀！”贵族说，“按戏班数量排队，当然是我家的戏班机会多。”

皇帝看向博士。

博士拿出一杆金灿灿的小秤。

“这叫**公平秤**。”他说，“它按‘主人’分配，不按‘戏班个数’分配。每个主人分到一份舞台时间，然后把自己那份分给自己的戏班。”

“这叫**公平共享调度（fair-share scheduling）**。如果贵族和村子各占一半份额，那么贵族的一百个戏班合起来只拿一半舞台时间，每个戏班只能分到一点点；村子的一个戏班拿另一半，就能很快上台。”

“所以，**公平不等于平均**。”博士说，“平均是每个戏班一样多。公平是按规则、按份额分。份额可以一样，也可以不一样；但每个主人都不会被忘掉。”

胖博士补充：“公平秤还有几种花样：”

- **彩票调度**：每个戏班发彩票，管理员随机抽一张，抽中谁谁上。彩票多的戏班中奖概率高。它简单、灵活，但短期有随机性。
- **步长调度**：每个戏班有一个“步长”，彩票越多，步长越小；管理员每次选“步数”最小的戏班。它是确定性的，长期公平。
- **Linux 的 CFS（完全公平调度器）**：给每个戏班记一个“虚拟运行时间”，每次选虚拟运行时间最小的戏班；用红黑树来快速查找；根据 nice 值给不同权重，实现按权重的公平。

“CFS 就像一杆特别聪明的公平秤。”博士说，“它不设固定的时间片。每个戏班按照自己的权重，公平地分享舞台。”

皇帝问：“那公平和效率，能同时要吗？”

博士说：“很难。公平秤可能让短戏班多等一会儿，吞吐量也不一定最高。但一个剧场如果只有效率没有公平，迟早会有人饿死；如果只有公平没有效率，观众又会等得不耐烦。你要在两者之间找平衡。”

## 第九场 组合拳与谢幕

马库斯把七只锦囊和公平秤摆在一起，想了很久。

最后，他设计了这样一套办法：

- **以多级反馈队列为骨架**：短戏班在高层快速完成，长戏班逐级下沉，但不会被忘掉；
- **高层用时间片轮转和优先级**：急报、宫廷戏班优先，普通戏班也能快速响应；
- **低层用 FCFS 或 RR**：保证长戏班最终能演完；
- **加老化**：等久了的戏班升一级，防止饥饿；
- **加公平秤**：按主人份额分配，防止一个贵族霸占舞台；
- **不同舞台用不同策略**：太阳台抢占式，月亮台非抢占式，星星台时间片轮转。

赏戏大会那天，剧场里热闹极了：

- 短喜剧一上台，几分钟就谢幕，观众笑得直拍手；
- 长篇史诗虽然沉到低队列，但每隔一段时间就能上台，最终也演完了；
- 急报戏班一到，立刻插到前面，皇帝很满意；
- 村子的戏班也上了台，村长激动得热泪盈眶；
- 舞台几乎没有闲着，吞吐量很高；
- 没有戏班饿死，观众也没有等得不耐烦。

皇帝高兴地说：“马库斯，你终于学会调度了！”

马库斯擦擦汗：“陛下，我只是记住了博士的话：**没有一种算法能包打天下，只有合适的组合。**”

博士们点点头：“对了。调度是权衡：响应时间、吞吐量、周转时间、公平性，常常互相冲突。你要明白剧场的目标，才能选规则。”

就在这时，弄臣又凑过来，叮叮当当地说：

“陛下，如果两个戏班同时抢同一件道具，怎么办？”

马库斯的脸又白了。

博士们笑了：“那是下一个故事：**同步与互斥**。”

大剧场的灯一盏盏熄灭。马库斯把今天的规则写进《剧场法典》。他知道，明天还会有新的难题。但只要记住：**看清楚目标之后，再选择规则；没有完美的算法，只有合适的算法。**

**第二幕完。**

## 1. 三级调度

### 1.1 高级调度（作业调度）

**别名：** 作业调度、长程调度、宏观调度。

**任务：** 从外存的后备队列中选择作业，为它分配内存、I/O 设备等资源，创建进程，插入就绪队列。它实现了**外存到内存**的调度。

**频率：** 低。一个作业通常只被调入一次，结束时退出一次。

**适用：** 主要用于**批处理系统**。分时系统和实时系统通常不需要或很少使用高级调度，因为它们要求及时响应，作业/进程的创建更直接，不会排成长长的后备队列。

> **【考点】** 高级调度＝作业调度；作业 → 进程；外存 → 内存；频率低；主要用于批处理系统。  
> **【易错】** 高级调度不是进程调度。进程调度是低级调度。

### 1.2 中级调度（内存调度）

**别名：** 内存调度、中程调度、交换调度。

**任务：** 把暂时不能运行的进程换出到外存（**挂起**），等条件具备时再换入内存（**激活**）。目的是提高内存利用率和系统吞吐量。

**频率：** 中等。可以发生多次。

**状态：** 引入挂起后，会出现**就绪挂起**和**阻塞挂起**：

- **就绪挂起**：进程本来可以运行，但被换出到外存，不在内存；
- **阻塞挂起**：进程在等待事件，同时被换出到外存。

> **【考点】** 中级调度＝内存调度；进程在内存和外存之间换入/换出；挂起/激活；进程已经存在，PCB 还在；可以发生多次。  
> **【易错】** 中级调度不创建进程；创建进程是高级调度的事。  
> **【易错】** 挂起不是终止；终止会回收 PCB，挂起只是把进程换出到外存。

### 1.3 低级调度（进程调度）

**别名：** 进程调度、短程调度、微观调度。

**任务：** 从就绪队列中选择一个进程，把 CPU 分配给它。它要做三件事：

1. 保存当前进程的 CPU 上下文到 PCB；
2. 按调度算法选择下一个进程；
3. 恢复所选进程的 CPU 上下文，分配 CPU。

**频率：** 高。分时系统、实时系统都离不开它。

> **【考点】** 低级调度＝进程调度；进程 → CPU；频率高；是调度器的核心。  
> **【考点】** 低级调度的三个任务：保存现场、选择进程、恢复现场。

### 1.4 三级调度的区别

| 对比 | 高级调度 | 中级调度 | 低级调度 |
|---|---|---|---|
| 别名 | 作业调度、长程调度 | 内存调度、交换调度 | 进程调度、短程调度 |
| 做什么 | 作业 → 进程 | 进程在内存/外存间换入换出 | 进程 → CPU |
| 对象 | 作业 | 已存在的进程 | 就绪进程 |
| 频率 | 低 | 中 | 高 |
| 主要目的 | 创建进程、控制多道程度 | 提高内存利用率、吞吐量 | 分配 CPU、提高响应 |
| 主要出现 | 批处理系统 | 多道程序、虚拟内存 | 分时、实时、通用系统 |
| 次数 | 一个作业通常一次 | 可多次 | 非常频繁 |

> **【高频考点】** 高级调度与中级调度的区别：  
> - 高级调度是“作业 → 进程”，创建进程。中级调度是“进程在内存和外存之间交换”，进程已经存在。  
> - 高级调度在作业生命周期中通常只调入一次、退出一次；中级调度可以发生多次。  
> - 高级调度主要面向批处理；中级调度面向内存管理/交换。

### 1.5 作业与进程的区别（补充）

| 对比 | 作业 | 进程 |
|---|---|---|
| 状态 | 静态 | 动态 |
| 位置 | 通常在外存后备队列 | 内存（或被换出） |
| 含义 | 用户提交的任务 | 任务的执行实例 |
| 关系 | 一个作业可包含多个进程 | 进程是作业的执行 |
| 调度 | 高级调度 | 低级调度 |

> **【补充】** 现代分时/实时系统中，“作业”这个概念用得越来越少，进程/线程是更基本的单位；但考试仍按教材的三级调度模型来考。

## 2. 进程调度的任务与组成

### 2.1 三个任务

1. **保存现场**：把当前进程的 CPU 上下文（寄存器、PC、栈指针等）保存到 PCB。
2. **选择进程**：按调度算法从就绪队列中选择一个进程。
3. **恢复现场**：从所选进程的 PCB 恢复 CPU 上下文，把 CPU 交给它。

### 2.2 调度器的组成

| 组成部分 | 作用 |
|---|---|
| 排队器 | 维护作业队列、就绪队列、阻塞队列；按规则插入/取出 PCB |
| 分派器 | 真正执行切换：从就绪队列取出选中进程，保存旧现场，恢复新现场，交出 CPU |
| 上下文切换器 | 保存/恢复 CPU 上下文；是分派器的一部分 |

> **【考点】** 调度器（scheduler）做决策，分派器（dispatcher）做动作。  
> **【易错】** 上下文切换既要保存旧进程现场，也要恢复新进程现场；不要只说“恢复”。

### 2.3 上下文切换的步骤

1. 保存当前进程的 CPU 上下文到其 PCB；
2. 更新 PCB 状态，把 PCB 移入相应队列；
3. 选择下一个进程；
4. 从下一个进程的 PCB 恢复 CPU 上下文；
5. 必要时切换地址空间（进程切换要换页表；同进程线程切换不用）。

> **【考点】** 上下文切换有开销；进程切换通常比同进程线程切换开销大。  
> **【补充】** 分派延迟（dispatch latency）：从停止一个进程到开始另一个进程的时间，包括保存/恢复现场、切换页表、刷新 TLB 等。实时系统很关心这个指标。

## 3. 调度时机

### 3.1 什么时候需要调度

1. **进程创建**：新进程进入就绪队列，可能触发调度。
2. **进程终止**：CPU 空闲，必须调度。
3. **进程阻塞**：进程等待 I/O/事件，CPU 空闲，必须调度。
4. **I/O 完成/事件发生**：阻塞进程被唤醒，进入就绪队列，可能触发调度；如果它优先级更高，可能抢占。
5. **时间片用完**：必须调度（抢占式）。
6. **更高优先级进程到达**：如果采用抢占式，可能抢占。
7. **进程主动让出 CPU**：如 `yield`、`sleep` 等（补充）。

> **【考点】** “必须调度”与“可能调度”要区分：  
> - 必须：进程终止、阻塞、时间片用完；  
> - 可能：进程创建、I/O 完成/唤醒、更高优先级进程到达（看策略）。

### 3.2 什么时候不能调度

1. **处理中断的过程中**：中断处理必须完成，不能中途切换进程，否则可能丢失中断/破坏现场。
2. **执行原子操作的过程中**：如修改 PCB 队列、修改内核数据结构；必须原子完成，否则会不一致。
3. **内核临界区中**：持有锁、访问临界资源时；切换可能导致死锁、竞争条件或优先级反转。

> **【考点】** 不能调度的情况：中断处理、原子操作、内核临界区。  
> **【补充】** 有些系统会设置“需要调度”标志，等退出临界区/中断处理后再调度；但考试通常按“这些情况下不能调度”作答。

## 4. 调度方式

### 4.1 非抢占式（非剥夺式）

**定义：** 一旦把 CPU 分配给某个进程，就让它一直运行，直到它终止或主动阻塞；其他进程不能强行夺走 CPU。

**优点：** 简单、开销小、适合批处理系统。

**缺点：** 响应时间可能长；一个长进程可能长时间霸占 CPU；不适合交互式/实时系统。

> **【易错】** 非抢占式不是“永远不调度”：进程终止、阻塞时，CPU 空了，当然要调度下一个；只是不会**强行**打断一个还能继续运行的进程。

### 4.2 抢占式（剥夺式）

**定义：** 操作系统有权在特定条件下暂停当前进程，把 CPU 分配给另一个进程。

**常见抢占条件：**

- 时间片用完（RR）；
- 更高优先级进程到达（优先级调度）；
- 更短剩余时间的进程到达（SRTN）；
- 中断/唤醒导致更高优先级进程就绪。

**优点：** 响应快、公平，适合分时/实时/交互式系统。

**缺点：** 上下文切换开销大；需要同步保护，否则可能引起竞争条件；实现复杂。

> **【考点】** 批处理系统多用非抢占式；分时/实时系统多用抢占式。  
> **【考点】** 抢占式≠一定更好；要看系统目标和开销。

### 4.3 对比

| 对比 | 非抢占式 | 抢占式 |
|---|---|---|
| 是否可强行打断 | 否 | 是 |
| 上下文切换 | 少 | 多 |
| 开销 | 小 | 大 |
| 响应时间 | 可能长 | 短 |
| 公平性 | 较弱 | 较强 |
| 适用 | 批处理 | 分时、实时、交互 |
| 例子 | FCFS、非抢占 SJF | RR、优先级、SRTN |

## 5. 调度评价指标

> 这一节的名词最容易混在一起。下面把每个指标分开讲清楚，并说明它们之间的区别。

### 5.1 CPU 利用率

```text
CPU 利用率 = CPU 有效工作时间 / (CPU 有效工作时间 + CPU 空闲等待时间)
```

- **有效工作时间**：CPU 正在执行用户/系统任务的时间；
- **空闲等待时间**：没有就绪进程、CPU 空闲的时间。

CPU 利用率高，说明 CPU 忙；但不是越高越好。如果高到“换景都来不及”，响应时间会变差。

> **【考点】** CPU 利用率＝忙时间÷（忙时间＋空闲时间）。  
> **【易错】** CPU 利用率不是吞吐量。CPU 可能 100% 忙，却在做大量无用功（抖动），吞吐量反而低。

### 5.2 吞吐量

```text
吞吐量 = 完成的作业数 / 时间
```

- 单位时间内完成的作业/进程数量；
- 吞吐量高，说明系统产出多；
- 批处理系统很看重吞吐量。

> **【易错】** 常见写法“单位系统内完成的作业数量”少了一个“时间”；正确说法是“**单位时间内**完成的作业数量”。

### 5.3 周转时间

```text
周转时间 = 完成时间 - 提交（到达）时间
         = 等待时间 + 运行时间
```

- 这里的“等待时间”是**广义**的：包括在就绪队列等 CPU、在阻塞队列等 I/O、等事件等所有等待；
- 周转时间越短，用户从提交到完成等得越少。

> **【考点】** 周转时间＝完成时间－到达时间＝等待时间＋运行时间。  
> **【易错】** 周转时间不是运行时间；它包含等待。

### 5.4 带权周转时间

```text
带权周转时间 = 周转时间 / 实际运行时间
             = 1 + 等待时间 / 实际运行时间
```

- 带权周转时间 ≥ 1；
- 越接近 1，说明等待越少；
- 它去掉了作业长短的影响：长作业天然周转时间长，短作业天然周转时间短，直接比不公平；除以运行时间后，可以相对公平地比较。

> **【考点】** 带权周转时间＝周转时间÷运行时间＝1＋等待÷运行。  
> **【易错】** 带权周转时间不能小于 1；在大于等于 1 的范围内，越接近 1 越好。

### 5.5 平均周转时间与平均带权周转时间

```text
平均周转时间     = (T1 + T2 + ... + Tn) / n
平均带权周转时间 = (W1 + W2 + ... + Wn) / n
```

- 用来比较不同调度算法的整体效果；
- 越小越好；
- 平均带权周转时间更适合比较不同长度的作业。

### 5.6 等待时间

**调度指标中的等待时间：**

> 进程在**就绪队列**中等待 CPU 的时间之和。

- 不包括进程在阻塞队列中等待 I/O/事件的时间；
- 如果进程被抢占多次，要把每次在就绪队列中等待的时间加起来；
- 等待时间越短，通常响应越好。

**注意：** 在“周转时间＝等待时间＋运行时间”这个公式里，“等待时间”是广义的，包含 I/O 等待等所有等待。两个“等待时间”含义不同，要看语境。

> **【考点】** 调度指标中的等待时间通常指就绪队列等待时间，不含 I/O 等待。  
> **【易错】** 不要把“等待时间”和“周转时间公式里的广义等待”混为一谈。

### 5.7 响应时间

**定义：**

> 从用户提交请求，到系统首次产生响应的时间。

- 对交互式系统：从按下回车到第一次看到输出；
- 对进程调度：常近似为“从进程到达，到它第一次获得 CPU”的时间（首次响应）；
- 响应时间关注“第一次”，不关注整个任务何时完成。

**与等待时间的区别：**

| 对比 | 等待时间 | 响应时间 |
|---|---|---|
| 关注点 | 在就绪队列中总共等了多久 | 从提交到第一次响应等了多久 |
| 是否包含多次等待 | 是，所有就绪等待之和 | 只看第一次响应前 |
| 典型用途 | 批处理、整体等待 | 交互式、实时性 |
| 例子 | 等 1 小时＋被抢占后再等 30 分钟＝1.5 小时 | 第一次上台前等了 1 小时＝1 小时 |

> **【考点】** 响应时间＝提交到首次响应；等待时间＝就绪队列等待总和。  
> **【易错】** 一个进程响应时间短，不代表等待时间短；它可能第一次很快上台，之后被反复抢占。

**例子：**

> 某进程 9:00 到达，10:00 第一次运行，运行 10 分钟；被抢占，等 30 分钟；10:50 运行 10 分钟后完成。
>
> - 响应时间＝1 小时；
> - 等待时间＝1 小时＋30 分钟＝1.5 小时；
> - 周转时间＝1 小时 50 分钟；
> - 运行时间＝20 分钟；
> - 带权周转时间＝110÷20＝5.5。

### 5.8 其他调度准则（补充）

- **公平性**：每个进程/用户都有机会获得 CPU，不能饥饿；
- **优先级**：重要/紧急任务优先；
- **资源平衡**：CPU、I/O 设备等资源要合理利用；
- **政策执行**：按系统政策分配资源；
- **可预测性**：实时系统要满足截止时间，延迟有界。

> **【考点】** 这些目标经常冲突，调度是权衡；没有一种算法能同时让所有指标最优。

## 6. 调度算法

### 6.1 先来先服务（FCFS）

**规则：** 按进程到达就绪队列的顺序调度，先到先服务；非抢占式。

**优点：**

- 实现简单，就绪队列可直接用 FIFO；
- 按到达顺序，直观；
- 一般不会饥饿（假设作业有限）。

**缺点：**

- **对长作业有利，对短作业不利**；
- 长作业在前会产生**护航效应（convoy effect）**，短作业和 I/O 繁忙型作业等待时间长；
- 平均等待时间可能较大；
- 不适合交互式系统。

> **【考点】** FCFS 非抢占；简单；对长作业有利；护航效应；短作业等待时间长。

### 6.2 短作业优先（SJF）

**规则：** 选择估计运行时间最短的进程；可以是**非抢占式 SJF**，也可以是**抢占式 SRTN**（最短剩余时间优先）。

**优点：**

- 在“所有作业同时到达、运行时间已知”的假设下，**平均等待时间最小**；
- 能显著改善短作业的等待时间。

**缺点：**

- 需要预先知道/估计运行时间；
- 长作业可能**饥饿**；
- 用户可能谎报运行时间；
- 对交互式系统不一定友好（除非配合老化/抢占）。

> **【考点】** SJF 可以非抢占，也可以抢占（SRTN）；平均等待时间在假设下最优；需要估计运行时间；长作业可能饥饿。  
> **【易错】** “SJF 一定最优”有前提：作业同时到达、运行时间已知、非抢占。到达时间不同或采用抢占时，结论要具体分析。

### 6.3 高响应比优先（HRRN）

**规则：**

```text
响应比 = (等待时间 + 估计运行时间) / 估计运行时间
       = 1 + 等待时间 / 估计运行时间
```

选择响应比最高的进程；通常**非抢占式**。

**优点：**

- 兼顾短作业和长作业：短作业分母小，响应比容易高；长作业等待越久，分子越大，响应比也会升高；
- **不会饥饿**；
- 是 FCFS 和 SJF 的折中。

**缺点：**

- 需要估计运行时间；
- 每次选择都要计算响应比，有开销；
- 非抢占，响应时间不一定很好。

> **【考点】** 响应比公式；选最高者；通常非抢占；不会饥饿；需要估计运行时间。  
> **【易错】** 响应比不是响应时间。

### 6.4 优先级调度

**规则：** 选择优先级最高的进程；可以是抢占式或非抢占式；优先级可以是静态或动态。

- **静态优先级**：创建时确定，运行期间不变；
- **动态优先级**：根据等待时间、已运行时间等因素调整。

**优点：**

- 灵活，能体现任务的重要性/紧急性；
- 适合实时系统、交互式系统；
- 可与其他算法结合。

**缺点：**

- 低优先级进程可能**饥饿**；
- 静态优先级可能不公平；
- 动态优先级需要调参；
- 可能出现**优先级反转**（补充）。

**解决饥饿：老化（aging）**——随着等待时间增加，逐步提高优先级。

> **【考点】** 优先级调度分静态/动态、抢占/非抢占；低优先级可能饥饿；老化可解决饥饿。  
> **【补充】** 优先级反转：低优先级进程持有锁，高优先级进程等待它；解决办法包括优先级继承、优先级天花板等。

### 6.5 时间片轮转（RR）

**规则：** 就绪队列按 FIFO 排列；每个进程获得一个固定时间片；时间片用完就抢占，放到队尾；抢占式。

**优点：**

- 响应时间短，适合分时/交互式系统；
- 公平，每个进程都能定期获得 CPU；
- 一般不会饥饿。

**缺点：**

- 上下文切换开销；
- 时间片太大→退化为 FCFS；
- 时间片太小→切换过于频繁，CPU 有效利用率下降；
- 平均周转时间可能不如 SJF。

> **【考点】** RR 抢占式；时间片太大→FCFS；太小→上下文切换开销大；响应快；适合分时系统。  
> **【考点】** 时间片的选择是 RR 的关键参数。

### 6.6 多级队列调度

**规则：** 将就绪队列分成多个队列，每个队列有不同的优先级；每个队列可采用不同的调度算法；进程通常**固定**在某个队列中，不能在队列间移动。

**优点：**

- 适合不同类型的进程（系统进程、交互进程、批处理进程）；
- 每个队列可以定制算法；
- 实现相对简单。

**缺点：**

- 低优先级队列可能**饥饿**；
- 进程不能移动，不够灵活；
- 队列划分和优先级需要设计。

> **【考点】** 多级队列：多个队列、队列优先级、每个队列自己的算法；进程通常不移动；低优先级可能饥饿。  
> **【易错】** 多级队列 ≠ 多级反馈队列；前者通常不能移动，后者可以。

### 6.7 多级反馈队列（MLFQ）

**规则：**

1. 设置多个队列，编号 0～N，数字越小优先级越高；
2. 每个队列按 RR 调度；优先级越高，时间片越小；
3. 新进程进入队列 0；
4. 如果在时间片内没完成，降到下一级队列的队尾；
5. 只有高优先级队列全空，才调度低优先级队列；
6. 低优先级队列中等待太久的进程可以升级（老化）；
7. 最低队列可用 FCFS/RR，保证最终完成。

**优点：**

- 不需要预先知道运行时间；
- 能根据实际行为调整：短作业留在高层，长作业下沉；
- 兼顾批处理和交互式；
- 最灵活，能近似 SJF 的效果；
- 老化可防止饥饿。

**缺点：**

- 参数多：队列数、时间片、升降级规则等；
- 实现复杂；
- 调参困难；
- 设计不好可能抖动/不公平。

> **【考点】** MLFQ 的队列优先级、时间片、降级/升级规则；只有高优先级队列全空才调度低优先级；适合批处理和交互式；最灵活；参数多。  
> **【易错】** MLFQ 可以在队列间移动；多级队列通常不能。

### 6.8 公平共享调度（补充）

**公平共享调度（fair-share）：**

- 按用户/组的份额分配 CPU 时间，而不是只按进程数；
- 如果某用户进程多，每个进程分到的份额就少；防止一个用户垄断 CPU；
- 可与优先级、多级队列结合。

**彩票调度（lottery）：**

- 每个进程/用户分到彩票；
- 调度器随机抽一张，抽中谁谁运行；
- 彩票越多，概率越高；
- 简单、灵活，但短期有随机性。

**步长调度（stride）：**

- 每个进程的步长＝常数÷彩票数；
- 每次选择“步数（pass）”最小的进程；
- 运行后 pass 加上步长；
- 确定性、按比例公平，长期可预测。

**Linux CFS（完全公平调度器，拓展）：**

- 给每个任务维护**虚拟运行时间（vruntime）**；
- 每次选择 vruntime 最小的任务；
- 用**红黑树**维护，查找效率高；
- nice 值决定权重：nice 越低，权重越高，vruntime 增长越慢，获得 CPU 越多；
- 不依赖固定时间片，追求按权重的公平。

> **【考点】** 公平共享按份额分配；彩票按概率；步长按确定性比例；CFS 用 vruntime＋红黑树＋nice 权重。  
> **【易错】** 公平≠平均；公平是按份额/权重分配，平均是每人一样。

### 6.9 算法对比

| 算法 | 抢占？ | 优点 | 缺点 | 饥饿？ | 适用 |
|---|---|---|---|---|---|
| FCFS | 非抢占 | 简单、直观 | 护航效应、短作业不利 | 一般不会 | 批处理 |
| SJF | 非抢占/抢占（SRTN） | 平均等待时间优 | 需估计运行时间、长作业饥饿 | 会长作业饥饿 | 批处理 |
| HRRN | 非抢占 | 兼顾长短、不会饥饿 | 需估计运行时间、计算开销 | 不会 | 批处理 |
| 优先级 | 可抢占/非抢占 | 灵活、体现重要性 | 低优先级饥饿、优先级反转 | 可能 | 实时、交互 |
| RR | 抢占 | 响应快、公平 | 上下文切换开销、时间片难选 | 一般不会 | 分时 |
| 多级队列 | 可抢占/非抢占 | 分类管理、各队列定制 | 低优先级饥饿、不灵活 | 可能 | 多类型作业 |
| MLFQ | 抢占 | 灵活、适应性强、兼顾批处理和交互 | 参数多、实现复杂 | 老化可避免 | 通用 |
| 公平共享/CFS | 抢占 | 按份额公平、防垄断 | 不追求最短周转、实现有开销 | 一般不会 | 多用户、通用 |

> **【考点】** 没有一种算法在所有指标上都最优；选择算法要看系统目标：  
> - 批处理：吞吐量、CPU 利用率、周转时间；FCFS、SJF、HRRN。  
> - 分时/交互：响应时间、公平性；RR、MLFQ、优先级。  
> - 实时：截止时间、可预测性；优先级、抢占式。  
> - 多用户：公平性；公平共享、CFS。

## 7. 小例题

> 这一题用来练“画甘特图＋算指标”。先别看答案，自己算一遍。

**题目：** 有三个进程：

| 进程 | 到达时间 | 运行时间 |
|---|---|---|
| P1 | 0 | 7 |
| P2 | 2 | 4 |
| P3 | 4 | 1 |

分别计算 FCFS、非抢占 SJF、时间片为 2 的 RR 的平均周转时间、平均等待时间、平均带权周转时间。

### 7.1 FCFS

执行顺序：P1（0–7）→ P2（7–11）→ P3（11–12）。

| 进程 | 完成时间 | 周转时间 | 等待时间 | 带权周转时间 |
|---|---|---|---|---|
| P1 | 7 | 7 | 0 | 7/7＝1 |
| P2 | 11 | 9 | 5 | 9/4＝2.25 |
| P3 | 12 | 8 | 7 | 8/1＝8 |

- 平均周转时间＝(7＋9＋8)÷3＝**8**
- 平均等待时间＝(0＋5＋7)÷3＝**4**
- 平均带权周转时间＝(1＋2.25＋8)÷3＝**3.75**

> 你看，P3 只运行 1 分钟，却等了 7 分钟，带权周转时间高达 8。FCFS 对短作业很不友好。

### 7.2 非抢占 SJF

t＝0 时只有 P1，先运行 P1（0–7）。t＝7 时，P2（需 4）和 P3（需 1）都在等，选 P3（7–8），再选 P2（8–12）。

| 进程 | 完成时间 | 周转时间 | 等待时间 | 带权周转时间 |
|---|---|---|---|---|
| P1 | 7 | 7 | 0 | 1 |
| P2 | 12 | 10 | 6 | 10/4＝2.5 |
| P3 | 8 | 4 | 3 | 4/1＝4 |

- 平均周转时间＝(7＋10＋4)÷3＝**7**
- 平均等待时间＝(0＋6＋3)÷3＝**3**
- 平均带权周转时间＝(1＋2.5＋4)÷3＝**2.5**

> SJF 改善了平均值，但 P2 等得更久了。这就是“平均最优”不等于“每个作业都最优”。

### 7.3 时间片为 2 的 RR

> 约定：新到达的进程先进入就绪队列；时间片用完的进程再排到队尾。不同教材对“同一时刻到达/时间片用完”的先后顺序可能略有不同，做题时要按题目约定来；这里把约定写清楚，避免歧义。

执行过程：

```text
P1(0-2) → P2(2-4) → P1(4-6) → P3(6-7，完成)
        → P2(7-9，完成) → P1(9-12，完成)
```

| 进程 | 完成时间 | 周转时间 | 等待时间 | 带权周转时间 |
|---|---|---|---|---|
| P1 | 12 | 12 | 5 | 12/7≈1.71 |
| P2 | 9 | 7 | 3 | 7/4＝1.75 |
| P3 | 7 | 3 | 2 | 3/1＝3 |

- 平均周转时间＝(12＋7＋3)÷3＝**22/3≈7.33**
- 平均等待时间＝(5＋3＋2)÷3＝**10/3≈3.33**
- 平均带权周转时间＝(12/7＋7/4＋3)÷3≈**2.15**

> 本题里 RR 让短作业 P3 比 FCFS 更早完成，但 P1 被反复打断，平均周转时间不如 SJF；实际系统还要计入上下文切换开销。不同算法、不同指标各有取舍；做题时一定要**按题目给的时间轴画甘特图**，不要死背结论。

### 7.4 一个提醒

如果题目说“所有作业同时到达”，SJF 的平均等待时间最小；如果到达时间不同，就要具体分析。**SRTN（抢占式最短剩余时间优先）** 可能在陆续到达的场景中表现更好。

## 8. 高频考点速记

1. **三级调度**：高级＝作业调度（作业→进程，外存→内存）；中级＝内存调度（换入/换出，挂起/激活）；低级＝进程调度（进程→CPU）。
2. 高级调度主要用于**批处理系统**；分时/实时系统通常不需要或很少使用。
3. 高级调度在作业生命周期中通常**只调入一次、退出一次**；中级调度可以**多次**。
4. 中级调度不创建进程；进程已经存在，PCB 还在；挂起不是终止。
5. 低级调度的三个任务：**保存现场、选择进程、恢复现场**。
6. 调度器组成：**排队器、分派器、上下文切换器**；调度器决定，分派器执行。
7. 调度时机：创建、终止、阻塞、I/O 完成/唤醒、时间片用完、更高优先级到达。
8. 不能调度：**中断处理、原子操作、内核临界区**。
9. **抢占式**：可强行打断；响应快、开销大；分时/实时常用。**非抢占式**：不强行打断；简单、开销小；批处理常用。
10. **CPU 利用率**＝忙÷（忙＋空闲）；**吞吐量**＝单位时间完成作业数。
11. **周转时间**＝完成－到达＝等待＋运行；**带权周转时间**＝周转÷运行＝1＋等待÷运行。
12. **等待时间**：就绪队列等待时间（不含 I/O 等待）；**响应时间**：提交到首次响应。两者不同。
13. **FCFS**：非抢占；简单；对长作业有利；护航效应。
14. **SJF**：非抢占/抢占（SRTN）；平均等待时间在假设下最优；需估计运行时间；长作业可能饥饿。
15. **HRRN**：响应比＝（等待＋运行）÷运行；非抢占；不会饥饿；需估计运行时间。
16. **优先级**：静态/动态；抢占/非抢占；低优先级饥饿；老化解决；注意优先级反转。
17. **RR**：抢占；时间片太大→FCFS；太小→上下文切换开销；响应快；适合分时。
18. **多级队列**：多个队列、固定优先级、各队列自己的算法；进程通常不移动；低优先级可能饥饿。
19. **MLFQ**：多队列、时间片随优先级变化、降级/升级、只有高优先级队列空才调度低优先级；最灵活；参数多。
20. **公平共享/彩票/步长/CFS**：按份额/概率/步长/vruntime 公平分配；公平≠平均。
21. 没有一种算法在所有指标上最优；按系统目标选择、组合、调参。
22. 计算题的第一步是画**甘特图**，第二步计算完成时间、周转时间、等待时间、带权周转时间。

### 8.1 常见考法

- **选择题**：判断算法是否抢占、是否饥饿、时间片大小的影响、三级调度的区别、等待时间/响应时间的区别。
- **简答题**：三级调度的区别；调度时机；抢占/非抢占；MLFQ 规则；公平调度与“公平/平均”的区别。
- **计算题**：画甘特图，算完成时间、周转时间、等待时间、带权周转时间；比较 FCFS/SJF/RR/HRRN 的平均指标。

## 9. 易错点纠正

| 常见误区 | 正确说法 |
|---|---|
| 高级调度就是进程调度 | 高级调度是作业调度。低级调度才是进程调度。 |
| 高级调度在分时/实时系统中很常见 | 高级调度主要用于批处理；分时/实时系统通常不需要或很少使用。 |
| 中级调度创建进程 | 高级调度创建进程；中级调度交换已经存在的进程。 |
| 中级调度只发生一次 | 中级调度可以发生多次（换出/换入）。 |
| 高级调度和中级调度没区别 | 高级：作业→进程，外存→内存；中级：进程在内存/外存间交换。 |
| 挂起就是终止 | 挂起只是换出到外存，PCB 还在；终止会回收 PCB。 |
| 调度就是分派 | 调度器决定谁上；分派器真正执行切换。 |
| 上下文切换只需要恢复现场 | 既要保存旧进程现场，也要恢复新进程现场。 |
| 任何时候都可以调度 | 中断处理、原子操作、内核临界区中不能调度。 |
| 抢占式一定比非抢占式好 | 各有优缺点；批处理常用非抢占，分时/实时常用抢占。 |
| CPU 利用率越高越好 | 不是；要平衡响应时间、吞吐量等。 |
| 吞吐量就是 CPU 利用率 | 吞吐量＝单位时间完成作业数。CPU 利用率＝忙时间比例。两者不同。 |
| 周转时间就是运行时间 | 周转时间＝等待时间＋运行时间，包含等待。 |
| 等待时间包括 I/O 等待 | 调度指标中的等待时间通常只算就绪队列等待；周转公式里的“等待”才是广义的。 |
| 响应时间就是等待时间 | 响应时间只看第一次响应。等待时间是就绪等待总和。 |
| 带权周转时间越小越好，可以小于 1 | 带权周转时间 ≥ 1；越接近 1 越好。 |
| FCFS 对短作业有利 | FCFS 对长作业有利，对短作业不利；可能有护航效应。 |
| SJF 永远最优 | SJF 的“最优”有前提：同时到达、运行时间已知、非抢占；否则要具体分析。 |
| HRRN 是抢占式 | HRRN 通常是**非抢占式**。 |
| 优先级调度不会饥饿 | 低优先级可能饥饿；需要老化。 |
| RR 时间片越大越好 | 太大→FCFS；太小→上下文切换开销大；要取平衡。 |
| 多级队列可以在队列间随便移动 | 多级队列通常固定；MLFQ 才允许移动。 |
| MLFQ 只适合批处理 | MLFQ 兼顾批处理和交互式，是最灵活的算法之一。 |
| 公平就是平均 | 公平是按份额/权重。平均是每人一样。公平≠平均。 |
| CFS 用固定时间片 | CFS 用虚拟运行时间和红黑树，不依赖固定时间片（或使用目标延迟）。 |
| 作业就是进程 | 作业是用户任务，静态。进程是执行实例，动态。一个作业可以包含多个进程。 |
| “单位系统内完成的作业数量” | 应为“**单位时间内**完成的作业数量”。 |
| 响应比就是响应时间 | 响应比是 HRRN 的公式。响应时间是另一个指标。 |
| 中断处理中可以调度 | 一般不能；应先完成中断处理。 |
| 原子操作中可以调度 | 不能；必须保证原子性。 |
| 所有算法都适合所有系统 | 不是；要按系统目标选择。 |
